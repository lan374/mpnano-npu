# 项目与联合方案

## 职责和链路

原 DeepStream/GStreamer 从视频识别目标，将每轮裁剪图写入目录；原分割程序继续读取这些原图。sender 只读目录，生成缩放编码后的 JPEG 预览回传。它不接管视频、飞控串口或原分割程序。

```text
裁剪目录 → 原分割程序
    ↓ 只读
sender：稳定检查 → SQLite/预览缓存 → 逐图TCP/ACK
    ↓ Jetson eth0
HM30天空端 → 无线链路 → HM30地面端 → LAN → Windows MP
    MP接收核心：校验/持久保存/ACK → 四图窗口按序轮换
```

飞控串口接天空端，地面 Type-C 用于既有飞控连接；图片使用地面 LAN。WLAN SSH 仅管理，不能把 SSH 或飞控连接成功当作图片链路成功。

## 数据约定

每轮图片目录起始为空，从0按数字命名，支持 jpg/jpeg/png。路径可在不同轮次相同，但必须使用新任务状态；同一序号不要出现多个扩展名或重复覆写。任务身份来自 sender 状态，不是目录名。

sender 每次仅一张等待 ACK。TCP 外还有长度、SHA256、任务/序号校验；地面确认发生在校验和持久保存之后，不等待 UI 显示。源图和预览字节不同，分别保留身份哈希。

网络故障保留队首并退避重连，不消耗坏图重试预算。单图内容失败默认初次加3次重试，最终告警跳过；地面存储故障保留天空队列。没有自动降画质或射频丢包率测量。

接收与显示解耦，预览落地后可慢速观看及恢复回看。四格每次换一格，显示间隔与传输限速独立；接收更快不代表观看积压消失。当前保留全部有效图，不自动只取最新图。

## 部署边界

sender 的 Python API 管理发送子进程，start/stop/status 由原管线任务生命周期调用。网络等待不会直接堵塞识别线程，但 CPU、磁盘和内存仍共享，要在实际推理负载下验证。

MP 在独立 MissionPlanner 工作区的 feature/hm30-p3-images 分支维护。独立 receiver 程序不再是正常用户入口，接收核心尚未迁入 MP，暂保留本地 receiver 路径供 MP 构建但不提交天空端公开仓库；完整地面构建需待 MP 仓库收齐依赖。

文档以天空192.0.2.40/24、电脑192.0.2.30/24、TCP8765示意；192.0.2.0/24为文档专用网段，不是设备默认值或现场地址，部署时必须替换。地址可以修改，必须核对实际网卡与路由。Jetson临时地址可能在重启后丢失；模块安装不会自动配置网卡、防火墙或自启服务。
