## 历史真实链路成果（封装前版本）

- Jetson Ubuntu20.04/Python3.8/ARM64，经Jetson有线网口→HM30→Windows有线网口的TCP服务，实际MP收到预览。WLAN SSH仅作管理。
- 同组200张在128/256/512KiB/s三档均全部确认、落盘哈希匹配、顺序显示。用户当时报告飞控已连接、未观察到异常；没有独立MAVLink丢包/时延量化。
- 发送循环优化后的200张256KiB/s：15.744秒确认，全部显示；相较19.273秒的差异受到无线和显示负载变化影响，不应全归因于代码改进。
- 新版地面诊断回归200张：14.988秒确认，零NACK、发送期间零断连，200张首轮顺序显示，零跳图。
- Jetson发送进程被强杀时已确认4/24，同任务状态重启后24张全部确认、哈希匹配、首轮显示；随后手动回放，48条显示事件仍只有24张唯一图片。
- MP图片接收服务停止时16张保留、内容重试0；恢复后同一发送进程自动重连，16张全部确认/匹配/显示。主动停收期间4次连接失败不是射频丢包率。

上述最后三项共240张，完整旧报告为 docs-pre-mis/P3新版真实链路验收-20261010.md，原始证据为 artifacts-mis/acceptance-live-20261010-01/。原图校验无改动。200张保存平均17.218ms（持久写入13.271ms），地面ACK写出0.119ms，天空等ACK30.740ms；成功样本不能代表失败尾延迟，也不能相减当作纯RTT。

## 尚未完成

1. **本次API/候选包**在Jetson上的新装、原管线接入和重启验收；历史CLI成功不能替代新接口验收。
2. Ubuntu22.04、真实GStreamer裁剪写入方式、与推理/分割共存的CPU、内存和I/O负载。
3. HM30物理断链、弱信号/射频干扰、MAVLink共存量化及长时运行。
4. MP宿主崩溃/重启后的显示恢复、真正掉电、磁盘不足与配额异常。进程强杀不等于设备断电，接收服务停启不等于MP宿主重启。
5. MP接收核心迁移以及另一对话的新任务/历史回看交互，须以其交付证据为准。

因此当前发行物标为测试候选版，不宣称完整现场验收结束。记录数、应用ACK数与射频送达率不同；显示日志表示交给控件，不证明人已看清。

## 构建与复验范围

```bash
python -m pip install "setuptools>=61,<76" wheel
python build_sender.py
```

构建脚本在build-mis内暂存源码，dist-mis/sender输出wheel、文档候选zip及SHA256清单。也可通过--wheel显式复用已经验证的wheel，脚本会逐文件核对sender源码。构建脚本不会自动安装到Jetson或配置MP。
